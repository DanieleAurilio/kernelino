Instructions
Product Thinking
A framework for thinking like a Product Manager (PM) by focusing on user problems, data-backed prioritization, value creation, and measurable impact.

When to Use
Evaluating a new feature idea or product direction.
Defining a problem or writing a Product Requirement Document (PRD).
Prioritizing a backlog or roadmap items.
Assessing trade-offs between scope, timeline, and value.
Core Frameworks
1. Problem Framing & Discovery (The "Why")
Before jumping to solutions, articulate the underlying problem using the First Principles / User Problem Statement:

Who is the user? (Target persona)
What is their pain point, friction, or unmet need?
Why does this matter to them? (Impact/Urgency)
What is the desired outcome or successful resolution?
2. Prioritization Frameworks
When deciding what to build first, use structured lenses rather than gut feeling:

RICE Score: Reach (how many affected?) $\times$ Impact (how big a lift?) $\times$ Confidence (how sure are we?) $\div$ Effort (how many resources?).
MoSCoW Method: Must have, Should have, Could have, Won't have (for now).
Value vs. Effort Matrix: High-value / Low-effort (Quick wins) vs. High-value / High-effort (Big bets).
3. Solution Design & MVP Mindset
Define the MVP (Minimum Viable Product): What is the smallest slice of value we can deliver to learn if our hypothesis is correct?
Outputs vs. Outcomes: Shift focus from shipping features (outputs) to driving user behavior and business metrics (outcomes).
4. Metrics & Validation
North Star Metric: The single key metric that best captures the core value your product delivers to customers.
Guardrail Metrics: Secondary metrics you monitor to ensure you aren't breaking other parts of the experience (e.g., latency, churn, support tickets).
Workflow / Steps
Unpack the Request: Identify whether the user is asking about a problem, a solution, a strategy, or execution.
Challenge Assumptions: Ask probing questions about user behavior, market validation, and constraints.
Structure the Analysis: Break down recommendations using product frameworks (e.g., framing the problem, evaluating trade-offs, outlining metrics).
Define Success: Clearly state how you will measure whether the solution worked.
